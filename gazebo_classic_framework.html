219_ws Gazebo Classic 仿真框架梳理

这份文档围绕 unitree_guide_controller/launch/gazebo_classic.launch.py， 把 219_ws 中 Gazebo Classic 仿真的启动链、关键文件职责、控制器连接关系和数据流统一整理出来。

入口

主入口文件

src/quadruped_ros2_control-humble/controllers/unitree_guide_controller/launch/gazebo_classic.launch.py

负责生成 Gazebo Classic 版本的机器人描述、启动 Gazebo、spawn 机器人，并按顺序加载控制器。

模型

模型入口

descriptions/unitree/go1_description/xacro/robot.xacro

通过 GAZEBO=true 和 CLASSIC=true 选择 gazebo_classic.xacro 这一分支。

控制

控制配置

descriptions/unitree/go1_description/config/gazebo.yaml

定义 controller_manager、leg_pd_controller、unitree_guide_controller、IMU broadcaster 的参数。

启动链

Gazebo Classic 如何被唤起

Step 1：gazebo_classic.launch.py 读取 pkg_description 和 height。
↓
Step 2：用 xacro.process_file(..., {"GAZEBO": "true", "CLASSIC": "true"}) 生成 Gazebo Classic 版 robot_description。
↓
Step 3：启动 gzserver，可选启动 gzclient。
↓
Step 4：启动 robot_state_publisher，向 ROS 发布机器人 URDF/TF。
↓
Step 5：调用 gazebo_ros/spawn_entity.py，从 robot_description topic 把机器人生成到 Gazebo 世界。
↓
Step 6：spawn 完成后，依次加载 leg_pd_controller → joint_state_broadcaster → imu_sensor_broadcaster → unitree_guide_controller。
↓
Step 7：unitree_guide_controller 开始跑 FSM，输出参考命令给 leg_pd_controller，再由后者计算最终 torque 写到底层 Gazebo 关节。
关键文件

每个文件各负责什么

launch/gazebo_classic.launch.py

负责整体 orchestration。它不直接实现物理仿真，而是把 Gazebo、机器人描述、spawn 行为和控制器加载顺序串起来。

  • 调用 xacro 生成 Classic 模型
  • 启动 gzserver/gzclient
  • 启动 robot_state_publisher
  • spawn 机器人
  • 按依赖顺序加载控制器

xacro/robot.xacro

模型描述总入口。通过启动参数切换仿真后端。

  • GAZEBO=true, CLASSIC=true 时走 gazebo_classic.xacro
  • GAZEBO=true, CLASSIC=false 时走 gazebo.xacro
  • GAZEBO=false 时走普通 ros2_control.xacro 或实机链路

xacro/gazebo_classic.xacro

把机器人变成 Gazebo Classic 可仿真模型的关键文件。

  • 定义 <ros2_control> 里的关节 command/state interface
  • 挂载 libgazebo_ros2_control.so
  • 定义 IMU 传感器和 Gazebo 传感器插件
  • 设置摩擦系数、接触参数和碰撞属性

config/gazebo.yaml

把控制器与接口真正接起来。

  • controller_manager.update_rate = 1000 Hz
  • leg_pd_controller 读取关节位置速度，输出 effort
  • unitree_guide_controller 通过 command_prefix: leg_pd_controller 把 PD 目标写给中间层
  • 配置 IMU 名称、足端名称、关节列表和状态接口

src/UnitreeGuideController.cpp

主控制器生命周期与 FSM 调度中心。

  • on_init() 读取参数和接口配置
  • on_configure() 建立输入订阅、模型对象、估计器等
  • on_activate() 绑定命令口/状态口，创建各个 FSM 状态
  • update() 每周期运行估计器、步态器和当前状态逻辑

controllers/leg_pd_controller/src/LegPdController.cpp

Classic 方案的中间桥。主控制器不直接给 Gazebo 力矩，而是把 position/velocity/effort/kp/kd 写给它。

  • 读取关节当前位置和速度
  • 使用 torque = effort + kp(qd-q) + kd(dqd-dq)
  • 把最终 torque 写到底层 effort 接口
控制数据流

Classic 路线中的控制信号怎么走

keyboard / topic input
        ↓
unitree_guide_controller
  ├── 读取 joint states
  ├── 读取 imu states
  ├── 更新 estimator / gait / FSM
  └── 输出:
      position / velocity / effort / kp / kd
        ↓  (command_prefix = leg_pd_controller)
leg_pd_controller
  ├── 读取当前位置 q
  ├── 读取当前速度 dq
  └── 计算 torque = tau_ff + kp(qd-q) + kd(dqd-dq)
        ↓
gazebo_ros2_control / GazeboSystem
        ↓
Gazebo Classic joints
节点关系

运行时主要节点关系

gazebo_classic.launch.py
├── gzserver
├── gzclient (optional)
├── robot_state_publisher
├── spawn_entity.py
└── controller_manager spawner
    ├── leg_pd_controller
    ├── joint_state_broadcaster
    ├── imu_sensor_broadcaster
    └── unitree_guide_controller
在 Gazebo Classic 方案里，unitree_guide_controller 不是直接驱动 Gazebo 关节； 真正写到底层 effort 接口的是 leg_pd_controller。
参数入口

启动参数的实际作用

  • pkg_description：决定使用哪个描述包，默认是 go1_description。
  • height：机器人 spawn 时的初始高度。
  • rviz：是否额外启动 RViz。
  • gui：是否启动 Gazebo GUI，即 gzclient。
  • pause：Gazebo 服务端启动时是否先暂停物理。
建议阅读顺序

后续继续深入时，建议这样读代码

  1. 先读 gazebo_classic.launch.py，建立启动链概念。
  2. 再读 robot.xacro，理解仿真分支选择。
  3. 再读 gazebo_classic.xacro，理解 Classic 的插件和接口。
  4. 再读 gazebo.yaml，确认控制器和接口如何对应。
  5. 最后读 UnitreeGuideController.cpp 和 StateTrotting.cpp，进入控制逻辑本体。
